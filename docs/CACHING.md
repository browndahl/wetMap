# Caching and cache keys

- Frame key: `frames/<DMI item id>.webp`; immutable for one year. If DMI republishes an ID with changed bytes, worker must fail/alert rather than mutate a cached object.
- Manifest key: `frames/frames.json`; `max-age=60, stale-while-revalidate=300`, ETag from object/content hash.
- Nowcast keys: `nowcast/<observation id>-plus-<lead>.webp`; five-minute browser/CDN cache. `nowcast/nowcast.json`, the compact alert grid `nowcast/risk.json`, and high-resolution `nowcast/point-risk.json` use short-lived metadata plus byte-range point lookup. The binary point cube alternates between two slots so its metadata switch is atomic without accumulating immutable 5 MB objects. Verification uses 16 compressed ring slots under `nowcast/verification-cubes/`, enough for the 65-minute scoring window without unbounded storage. `verification-history.json` keeps the bounded calibration ledger privately in R2, while public `verification.json` exposes aggregate metrics plus at most 288 detailed forecast results and 24 gauge results. Duplicate scheduler runs do not re-upload unchanged verification assets. The UI rejects a nowcast that does not match the latest observation.
- Forecast key: API path plus latitude/longitude rounded to 2 decimals, 10-minute TTL, six-hour stale-while-revalidate allowance and last-known-good R2 storage under `forecast/v3/`. DMI EDR is primary; Open-Meteo is a latency/error hedge after a 1.5-second DMI head start.
- Next-hour model fallback key: API path plus coordinates rounded to 2 decimals, 5-minute TTL, 30-minute stale-while-revalidate allowance and only still-future persisted points under `precipitation/v2/`. DMI's cumulative precipitation is converted to hourly increments before being interpolated into 15-minute boxes. The public response is composed at coordinates rounded to 3 decimals from three small R2 byte ranges and cached at the edge for at most 60 seconds; only intervals without current radar coverage retain the cached HARMONIE value. This TTL expires well before a normal five-minute radar cycle while removing repeated R2 reads for the same selected point.
- Browser service worker keeps 24 observed/nowcast frames for two hours and 180 basemap responses for one day. It also receives Web Push events, but never contacts DMI directly.
- API in-memory cache is per replica; CDN is the shared cache. Do not add Redis until cache-hit metrics demonstrate a need.
